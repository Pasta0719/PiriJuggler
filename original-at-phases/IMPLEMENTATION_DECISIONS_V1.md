## A. 識別子・数値・素材

1. 新機種の永続`MachineType`は **`ORIGINAL_AT`**、管理画面での表示名は **`Piri AT`**。IDは既存8種を上書きしない。筐体表面にはロゴ/機種名テキストを描かない。`/piri machine create ORIGINAL_AT`、既存`/piri machine setting <id> <1..6>`、`/piri machine type <id> ORIGINAL_AT` を使う。未完成機は通常のホールへ自動投入しない。
2. 全確率・払い出し・AT/CZ遷移・付与枚数・引き戻し確率は **`pirijuggler_new_machine_calibrated_v5.json` を固定の実装基準**とする。演出の都合で払出・機械割を変更しない。設定1〜6の目標は97.0/99.3/102.5/104.8/107.4/116.0%。v5のMonte Carlo実測は96.97/99.17/102.55/104.79/107.29/115.78%であり、理論値や実Minecraft観測値とは混同しない。
3. 必要なユーザー製作画像は **7枚のみ**：`red7.png`, `rainbow7.png`, `bar.png`, `grape.png`, `replay.png`, `cherry.png`, `watermelon.png`。全て**透明背景RGBA PNG、256×256px、図柄を中央に収める**。受取先は`fabric/src/main/resources/assets/piri/textures/gui/original_at/symbols/`。図柄の一部が切れないようUI側で縦横比を維持して描画。**配列表・音・告知ランプ画像・筐体画像のユーザー制作は要求しない**。
4. 図柄画像が来る前は、固定の**図柄IDだけ**でPaper抽選・停止制御・テストを進める。画像表示のみ実ファイルに依存する。開発側でユーザーの図柄の代わりの完成画像を勝手に採用しない。
5. 3リールは [REEL_STRIPS_DRAFT_V1.json](REEL_STRIPS_DRAFT_V1.json) の**各21コマ**を採用。ハズレ・REPLAY・GRAPEは**0〜4コマ滑り保証**（全押し順、全押下位置）。スイカ・弱強チェリー・チャンス/強チャンス・BAR・AT赤7・CZ虹7は**目押し失敗なしの確定引込み**で必要なら0〜20コマ回す。実際の回転アニメーションを再生し、ワープしない。弱チェは中段左・中チェリー2個、強チェは中段3個。基本役ラインは**上・中・下・斜め2本の5ライン**。チャンス目、BAR、赤7、虹7、チェリー形は指定の**中段**を採用。ユーザーの最新「ok」に基づく配列設計に変更なし。
6. **3リール同時に当たり図柄の引込みが可能であること**を停止ソルバーで担保する。初停止で将来の合法な出目を塞がず、後続の押し順・押下位置すべてを満たす候補だけを採用。通常役4コマと確定役0〜20コマは別の停止ルールにする。払い出しはPaperの内部役に基づき、偽BAR・偽虹7・偽赤7の揃いを通常時に禁止。

## B. AT当選赤7と重複役の共存（決定）

7. 通常時の単独AT当選・役重複AT当選・BARによるAT直撃は、**元ゲームの内部役の停止・払出が第三停止で確定**したあと、**追加BET/払い出しなし・ゲーム数加算なし**の専用`AT_RED7_CONFIRM`アニメーションへ移る。3リールを再回転（自動）して**中段赤7・赤7・赤7を必ず停止**させる。したがってレア役の停止形とAT赤7を**同じゲーム内で両方表示**できる。これは新しい抽選ゲームではない。最初の成立役のメダル・当選結果を変えない。確定役BARでは**BAR揃いを先に見せ、次に赤7を見せる**のでどちらも省略しない。
8. 上位CZ成功は、中段**虹7揃いを成功結果**として見せ、そのまま上位初期へ移る。**CZ成功で追加の赤7再告知は行わない**（通常時の新規AT初当たりとは別経路）。下位CZ失敗後に新下位初期へ戻るときも、赤7再告知しない。AT初当たり1回に赤7を1回だけ表示する。
9. 赤7再回転は三リール同時に`720ms`で目標へ到達、最後の`320ms`静止点灯後に通常の下位/上位初期へ。演出中は新BET/停止を受けず、再接続時も`AT_RED7_CONFIRM`段階・正本インデックスを復元し、二重精算しない。効果音は後述の既存`notice`（BARの先行停止時は`notice_strong`）。

17. 上位初期5Gの合計が2,000枚ちょうどでも、**6G目のTOTALは新しい+2000上乗せではない**ため虹フラッシュを新たに発生させない。初期5Gの個別Gで`+2000`を本当に獲得した場合のみ虹ランプ/フラッシュを抽選可能にする。

## D. 右3灯・カラー・第三停止フラッシュ

18. 右縦3灯の位置は`(1583,370,34,34)`, `(1583,439,34,34)`, `(1583,508,34,34)`。色の強さは**白＜青＜緑＜黄＜紫＜赤＜虹**。ランプ3つはプレイヤーの停止操作と同期。**実際に正の上乗せが成立しているGに限り**レバーONで1灯点灯、第1/第2停止のどちらかで追加点灯または色変化（変化なしもあり）。**0枚加算のGは演出を発生させず全消灯**。上乗せなしで「白＝最低10枚」を破らないための確定ルール。
19. 最終色は第三停止までに決定し、配当の実額で下記テーブルを使う。色が表す最低枚数は**白10／青20／緑30／黄50／紫100／赤500／虹ちょうど2000**。上乗せが500以上でも赤が出ないことはある。2000が出ても虹は必須でない。2000超の累計TOTALには虹を出さない。虹は**単一の新規上乗せがちょうど2000**の時だけ。
20. 最終点灯数の抽選は色と独立。新規付与`10〜49`枚は1灯45%/2灯40%/3灯15%、`50〜199`は30/45/25%、`200〜499`は25/40/35%、`500以上`は15/35/50%。左液晶の初期TOTALは1G付与で計算し、第6Gの総計演出は**右演出の新規付与として扱わない**。
21. 最終色の選択：付与枚数を下表の範囲で分類し、各色の重みで1回抽選。役の種類は抽選色に影響させず、**枚数だけ**で決める（機械割とは独立）。区分外の一括付与は最も近い区分へ補間せず、`2001以上`行を使う。**10枚未満の新規付与は本v5には存在しないため演出なし**とする。

22. レバーでまず1灯。最終灯数が2なら第1停止で2灯にする確率50%、第2停止で2灯にする確率50%。最終3灯なら第1停止で2灯、第2停止で3灯。最終1灯なら追加しない。最終色`C`はレバー時点20%、第1停止時点40%、第2停止時点40%で確定色へ到達するよう抽選し、それ以前は**白**で始める。途中で色が上がることはあるが**色が下がることはない**。最初から1灯赤、最後まで3灯黄が両立する。到達前の白もそのゲームの上乗せが10以上であることはPaperが保証。
23. 第三停止で左液晶の新規付与`+N`と、**3リールすべてへの半透明フラッシュ**を同期。フラッシュは最終ランプ色と**80%同色／20%上位色昇格を試行**する。昇格先はその実付与金額に対して保証条件を満たす**全ての上位色から等確率選択**。候補0なら同色にする（無効な赤・虹を無理に出さない）。虹は`+2000`以外絶対不可。白/青/緑/黄/紫/赤の透明度はそれぞれ26/28/30/33/38/42%を上限とし、`80ms点灯→70ms消灯`を4回（計600ms）。虹は移動する多色グラデーション、透明度35%、同じ600ms。下地の全リールが常に読める程度の半透明を守る。
24. `AT_RED7_CONFIRM`、上位CZの虹7、通常のBAR揃いは**上乗せフラッシュとは別の成立演出**。第三停止の右3灯に関係ないBARや赤7で「赤は500以上」等を誤表示しない。演出開始・最終色・枚数・点灯数・段階ごとの時刻は**サーバー確定イベントID**で同期し、クライアント毎のランダムで違う保証色を出さない。

## E. CZ演出・音・状態・復帰

25. 上位CZレバーONから**500msで左中段虹7自動停止、700msで右中段虹7自動停止、900msで中央停止入力を解禁**。左右の停止操作は全期間拒否。中央の早押しは記録も消費もしない。中央を止めるタイミングと関係なく、Paperの事前当否が成功なら中段虹7揃い、失敗なら中段が外れる。CZはv5の最大5G、保証なし通算50%、保証有りは事前確定Gまでに必ず成功、0BET・0払出。
26. 効果音は当面**既存音源だけで実装**する。操作`lever/bet/stop`、通常告知と赤7`notice`、BAR`notice_strong`、小上乗せ`payout`、大上乗せ`notice_strong`、CZ左右停止`tenpai`、CZ成功`bonus_start`、CZ失敗`bonus_end`。ローカルで当該OGGがない場合のみその音だけを無音にし、ゲームと表示は止めない。**追加BGM／追加音源の納品は要件に含めず、実装完了のブロッカーとしない**。既存の音声距離減衰/遮蔽/観覧制限を継承する。固有音をユーザーが後日希望する場合に専用音IDを追加する。
27. 32G引き戻しは内部的にv5の**有料ゲームだけをカウント**。0BETリプレイによる無料通常遊技も「有料Gに含めない」というv5の現在の時間軸規則に従い、引き戻し期間を減らさない。自動引戻抽選と通常AT抽選は両方実行、同時当選でも下位初期の開始は1回だけ。BAR優先。
28. Paperは現在モード、当選元モード、連続役カウンタ、リプレイ権利、差枚、CZ権利と保証G、BARストック、赤7演出段階、AT初期5Gの各付与とTOTAL、6G表示キュー、停止履歴と演出イベントIDを原子的に永続化。**再起動/離席/回線再送でBETや賞金を二重計上しない**。Fabric観覧・遠隔とスマホは秘匿内部モードを配信せず、表示済み結果と公開状態だけを同期する。
29. データランプは履歴に**AT初当たり/上位昇格/CZ挑戦/CZ成否/BAR/総AT差枚/終了/引き戻し**を独立分類で記録し、BIG/REG件数を流用しない。管理・粗利・設定配分機能は`ORIGINAL_AT`を独立の機種カテゴリとして認識し、3BET、46枚貸し/52枚交換等の既存店舗計算を壊さない。
30. 無制限のAT残枚・通算付与を想定し、算術は**少なくとも符号付き64bit**を使用、明示的な差枚数上限・強制打切りは設けない。加算時のオーバーフローを黙って巻き戻さず、検証可能な明示エラーで停止・保全する。液晶の桁数は必要に応じて縮小する。
